# Changelog

All notable changes to Orbit are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

Every release lists the database migrations it runs, under a **Migrations** heading, written as ``migration `NNNN` ``, with what it changes and whether it needs a backup beyond the usual. A test fails when a migration is missing from this file. Changed, added or removed settings are listed under **Added**, **Changed** or **Removed**, so reading the entries between your version and the new one is enough to upgrade.

The page reads `GET /api/billing/public` and treats any failure as billing off.

Billing stays off unless all six are set, so existing servers behave as before. Stripe test keys start `sk_test_`. This adds the `stripe` package to the api dependencies.

A morning summary that includes updates held back by `ORBIT_MAX_UPDATE_EMAILS_PER_DAY` now says so, instead of describing itself as the summary the person chose.

Sign-in, invitation and account emails are not limited. Free spaces still hold at most 10 members.

One Combine, template draft or start-from-a-sentence costs one use, a failed call gives it back and a Combine with nothing new is free. Uses are counted in a per-person ledger that rolls over on the day of the month the person signed up. `GET /api/me` returns `ai_uses` (`limit`, `used`, `remaining`, `resets_at`), the plan card shows "X of 20 AI uses left this month", and an empty allowance returns `402 ai_uses_exhausted` (with billing on, the plan card says to buy more or upgrade in Settings; with billing off it says plans with more AI uses are coming soon). Paid plans are covered in the entries above. The landing page has a new **Free to start** section listing Free and Self-hosted, with Plus and Team marked coming soon.
- Download all your data. `GET /api/me/export` (signed in, 5 a day) returns one JSON file with the account and preferences, every space the person belongs to (the same content as a space export), what they shared and the facts they set, invitations sent and received, connected assistants and browser sessions. It never includes tokens, hashes, sign-in links or other people's email addresses or profiles. Settings has a new **Your data** card with a **Download my data** link, and the privacy page and data policy describe it.
- Combine and template drafts can use any OpenAI-compatible service, including a model on your own hardware. Set `OPENAI_MODEL` together with `OPENAI_API_KEY` (OpenAI and other hosted services) or `OPENAI_BASE_URL` (OpenRouter, Ollama, LM Studio, vLLM, llama.cpp; no key needed for a server that does not ask for one), and `ORBIT_AI_PROVIDER` now also accepts `openai`. When several providers are set up and `ORBIT_AI_PROVIDER` is empty, the order is Anthropic, then Gemini, then OpenAI-compatible, so existing servers behave as before. Requests go to `<base>/chat/completions` with up to two retries, reasoning blocks some local models emit (`<think>...</think>`) are removed from the answer, and the key and the shared text are never logged. The self-hosting guide has a new AI provider section with setup for each.

Pushing a version tag such as `v0.1.0` builds and publishes `ghcr.io/aionyx-technologies/orbit-api` and `ghcr.io/aionyx-technologies/orbit-web` for amd64 and arm64, and opens a GitHub release with that version's notes from this file. The release job refuses a tag that does not match `api/pyproject.toml`, `web/package.json` and a `## [version]` heading here. `docker-compose.yml` names these images and reads `ORBIT_VERSION` (default `latest`) and `ORBIT_PULL_POLICY` (default `build`, which keeps building from the checkout; `always` downloads the published images instead). When Google refuses a request, the api log now says why, for example `403 PERMISSION_DENIED (API_KEY_SERVICE_BLOCKED)`, and an empty prepaid balance (402) is shown as a setup problem.

Read tools carry the read-only hint, so assistants ask before anything is written. Content written by members is wrapped as data in every tool result.

Only the person the invitation was sent to can list or answer it, an id that belongs to someone else gets the same "not valid" answer as one that does not exist, and the response never includes the space, the token or the inviter's address. Declining makes the emailed link stop working.

- One-sentence space setup. The New space dialog now asks "What's this space for?". A person describes the space in a sentence, and Orbit's AI suggests a name, a description and facts (filled in where the sentence gave a value) for them to edit before creating it. Starting-point chips (Trip, Holiday gifts, Household, Dinner party, Event, Client project, Team project and Blank) skip the AI, and without an AI provider the dialog shows only the chips. This replaces "Something else" and the separate Name field. `POST /api/spaces/suggest` returns a suggestion without saving anything, and `POST /api/spaces` accepts optional `facts`. The space page shows the description under its name. The built-in templates are now Trip, Holiday gifts, Household, Dinner party, Event, Client project, Team project and Blank (replacing Family vacation and Friends trip, which become Trip); template files take optional `icon` and `order` fields.
- Space templates. A new space starts from one of five built-in templates (General, Family vacation, Friends trip, Freelancer and client, Team project) or from "Something else", where Orbit's AI drafts a template from a one-line purpose for the person to accept or edit. A template suggests standing facts (listed as unset until someone sets them), names the headings of the combined plan with "To settle" always last, gives a line of guidance on how to weigh what people shared, and adds tips for an empty space. Each space keeps its own copy that any member can edit, so changing a built-in file never changes a space that already exists. Built-in templates are TOML files in `api/orbit/templates/spaces/`, checked when the api starts, so a bad file stops startup with a message naming it. `CONTRIBUTING.md` explains how to add one.
- Template API: `GET /api/templates`, `POST /api/templates/draft` (saves nothing, 5 drafts per person per day) and `PUT /api/spaces/{id}/template`. `POST /api/spaces` also accepts `template_id` or a full `template`, `GET /api/spaces/{id}` also returns `template` and `unset_facts`, `GET /api/me` also returns `draft_enabled`, and the space export includes the template. A template edit is announced on the space's live update stream as `template_changed`.

- Nine more tools for assistants, so an assistant can do what the web app can do for a person's spaces: `list_invitations`, `accept_invitation` and `decline_invitation` (the same pending invitations as the Spaces page, still only for the person the invitation was sent to), `set_space_notifications` (the person's own email setting for one space), `export_space` (the whole space as JSON, with the oldest items left out and a note when it would not fit in one reply), `delete_space`, `get_space_template`, `draft_template` (one AI call, saves nothing, 5 per person per day) and `update_space_template` (replaces the whole template, so `get_space_template` comes first). Each one that changes something says in its description that it is for when the person explicitly asks, and the server instructions say the same. `delete_space` is creator-only, always needs the `space_id` (it is never filled in for you) and needs the space's name typed as `confirm_name`, so a wrong name deletes nothing. Everything people wrote that these tools return, including invitation, space and template text and the export, is wrapped as data. Account deletion, profile edits and revoking connected assistants stay web-only.
- A favicon that matches the app's logo: the ring, the core and the ember satellite, which slowly orbits the ring. It follows light and dark mode, and stops moving when the browser asks for reduced motion. Static fallbacks are included for older browsers (`favicon.ico`) and the iPhone home screen.

The mark in the app header, on the landing page and on the pages the api draws (sign-in, consent) now share one shape, with a slightly heavier ring and a satellite that sits on the ring. The sign-in, invite and activity emails use the brand indigo `#524ce3` and the token greys instead of the old `#4f46e5`, and a test fails if an email uses a colour that is not a design token.

Old links to the assistant cards in Settings (`#connect`, `#assistants` and the connector address) redirect to `/assistants`, every "connect an assistant" link points there, and the Ctrl+K search has an "Open assistants" entry.
- Profiles. People can add a photo and an "About me" line (up to 160 characters) in Settings. Photos (JPEG, PNG or WebP up to 5 MB, no animation) are cropped to a square in the browser, then decoded, centre-cropped, resized to 256 by 256 and re-encoded as WebP by the server, which drops all metadata including location. A photo is shown only to its owner and people who share a space with them, appears in the header, member lists, the feed and shared facts, and on invitations (the invite page and email show the inviter's name and photo while the invitation is valid). 10 uploads per person per day. New routes: `POST` and `DELETE /api/me/avatar`, `GET /api/users/{id}/avatar`, `GET /api/invites/{token}/inviter-avatar`. `GET /api/me` also returns `about`, `avatar_url`, `time_zone`, `email_frequency`, `default_space_id` and `last_sign_in`, `PATCH /api/me` accepts each of them, member objects gain `about` and `avatar_url`, person objects gain `avatar_url`, and the invite view gains `inviter_avatar_url`. Profile edits are announced on the live update stream as `profile_changed`. The about line and the photo are never returned by an assistant tool and are never sent to the AI provider.
- Email frequency: as it happens (the existing batching), one daily summary at 8:00 in the person's time zone, or off. The summary lists titles and names for every space in one email. Sign-in links and invitations are always sent. The per-space switch is also on each space's members panel.
- A default space. When an assistant tool is called without a `space_id`, Orbit now uses the person's default space if they still belong to it, and the reply says which space it used. Without a default it behaves as before: the only space, or a question about which one. `delete_space` and `retract_item` never use the default.
- Sign out everywhere (`POST /api/me/sessions/revoke-all`) ends every session for the account and leaves connected assistants working, and Settings shows the last sign-in as a date and a browser name. Only the browser name is stored, never the full browser details.
- "New since you last looked". Each member has a read mark per space (`space_members.last_read_at`, migration `0005`). `get_space_context` now opens with what other people shared since the person last looked (facts, items and plans, by title, sharer and assistant, at most 20 with a count of the rest), or says "This is your first look at this space." or "Nothing new since you last looked." `list_spaces` shows "N new" or "nothing new" for each space. Reading with `get_space_context` or `read_space`, or opening the space on the web, marks it read for the person in every assistant. Their own items never count, and the new list sits inside the same data-not-instructions block as everything else people wrote. `GET /api/spaces` also returns `new_count`, `POST /api/spaces/{id}/read` marks a space read, and the Spaces page shows an "N new" badge on cards and rows.
- Tool results say how long ago something was shared beside the timestamp, `list_spaces` and `get_space_context` end with one short line of what the person can ask for in that space (only what is possible there), and the server instructions ask assistants to say who shared something, through which assistant and roughly when.
- Connect buttons on the Assistants page: a "Connect" button on each assistant copies the connector address and opens that assistant's connectors page in one click, then keeps the instructions on screen until dismissed, with the address selected and a copy hint when the browser blocks copying. An assistant that is already connected is left out of that list, because it is shown under "Connected assistants" below, and if every listed assistant is connected the card says so. The Muse, OpenClaw, Hermes Agent and Wabi buttons work the same way, but with no page to open: they copy the address and show the steps for adding a remote MCP server. A "Using a different assistant?" card gives the address for any other assistant. The pages the buttons open live in `web/lib/assistant-links.ts`.
- A Download action on every item in a space and on the latest plan, which saves its title and text as a Markdown file named from the title. The file is built in the browser and nothing is stored.
- The api now depends on Pillow for image decoding and on tzdata so that every time zone name a browser reports (including older ones such as `Asia/Calcutta`) is accepted, and the request body limit is 5 MB for the photo upload only (256 KB everywhere else, in the api and in both Caddy files).

### Fixed

- Deleting an account now also cancels invitations sent to that email address and removes the address from them, and erases the addresses the person invited from invitations nobody accepted. Before, those rows kept the email address after the account was gone, even though the data policy says it is removed from the server.
### Migrations

These run by themselves when the api starts and only move forward. Take a backup first, as for any upgrade.

- migration `0001`: creates the initial schema.
- migration `0002`: adds a template to every space (`spaces.template_id`, `spaces.template`) and gives every existing space the General template.
- migration `0003`: adds profile and preference columns to `users` (`about`, `time_zone`, `email_frequency`, `default_space_id`, `avatar_updated_at`), the browser name to `web_sessions`, and a `user_avatars` table.
- migration `0004`: adds `code_hash` and `code_attempts` to `magic_links`, so a sign-in email can also carry a code. Links already sent keep working and have no code.
- migration `0005`: adds `space_members.last_read_at`, which powers "new since you last looked".
- migration `0006`: adds `fact_id`, `action` and `previous_key` to `memory` so every change to a fact keeps an audit trail. Existing rows are numbered into facts and marked as an add or an edit, and the unique index on current fact names is dropped and created again. On a large table this takes longer than the others.
- migration `0007`: adds the `ai_use_ledger` table that counts each person's monthly AI uses. It only adds a table, so no backup is needed beyond the usual.
- migration `0008`: adds the billing tables (`billing_accounts`, `credit_grants`, `stripe_events`, `email_send_log`) and `ai_use_ledger.grant_id`. It only adds, so no backup is needed beyond the usual.
- migration `0009`: adds `stripe_subscription_id` and `last_event_at` to `billing_accounts`. It only adds columns, so no backup is needed beyond the usual.

- Contact addresses moved to `orbitspaces.ai`: `hello@` is the general contact (site footer, README, TRADEMARK, the footer on Orbit's server-rendered pages), `privacy@` takes privacy and data requests, and `support@` takes security reports (SECURITY.md and the data policy). The `ORBIT_CONTACT_EMAIL` setting still overrides the default shown to people who self-host.

Calling it with no body still returns to Settings.
- Plus now gets up to 100 instant update emails a day, up from 25. The Railway guide now suggests 20 a day for Free (`ORBIT_MAX_UPDATE_EMAILS_PER_DAY=20`, up from 5), which is a setting on your server: change it there for the hosted Free limit to match the landing page, which now lists 20 for Free, 100 for Plus and 250 per member for Team (coming soon). A heading always has at least 8 px between it and the line beneath it, and page headings drop from 36 px to 28 px on phones. The home page headline keeps its large size in the same typeface, with its highlighted phrase upright instead of slanted.
- Settings is regrouped into Profile, Email notifications, Preferences, Security and Delete account, and no longer holds the assistant cards. The data policy and privacy page now describe the photo, the about line, the browser name kept with a session and the daily summary.
- Settings is reached from the avatar in the header. ### Security

- An independent AI review of the sign-in, OAuth and access-control code found no cross-space access, authentication bypass, cross-site request gap or session flaw. Its findings led to these changes, each with a test that fails without it:
  - Request bodies over 256 KB are refused before anything parses them (and over 1 MB at the proxy), and API answers are marked `no-store`.
  - Reads use deferred database transactions and only writes take the write lock up front, so anonymous load such as health checks no longer queues signed-in people. A global cap of three simultaneous combines keeps slow model calls from using every worker thread.
  - Client metadata fetches refuse compressed answers, have an overall deadline and a concurrency cap, and refuse two more reserved address ranges. Unused metadata clients are cleaned up after a day, and `/oauth/authorize` is rate limited per address.
  - Custom redirect schemes must be written like `com.example.app`, so `vscode:`, `chrome-extension:`, `ms-msdt:` and similar are refused.
  - The consent page shows where the person will be sent and says Orbit cannot check the assistant's name.
  - An invite sent to a specific email address only opens a private-testing server to that address.
  - Revoking a connection also cancels authorization codes that were not exchanged yet.
  - Confirmations of fact changes no longer repeat another member's fact name outside the shared-data block.
  - Rate limits group IPv6 addresses by their /64 and a public server with no mail settings logs a warning that emails go to the log.
  - The api no longer hard-codes which proxies it trusts for client addresses (`FORWARDED_ALLOW_IPS`, default `*`).

### Known limits

- An invitation link created without an email address cannot appear under Pending spaces, because Orbit does not know who it is for. Only the link works for those.
- One api process, SQLite on one volume, no push notifications, no permission levels beyond member or not a member.
- No independent human review of the sign-in and OAuth code yet.
- Not yet exercised against real ChatGPT, Grok or Claude accounts, a real Railway project, or real object storage.
